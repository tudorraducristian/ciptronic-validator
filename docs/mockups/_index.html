C Ciptronic Validator — Mockup-uri v0.2 · două fluxuri

Validare flow funcțional

8 pagini, organizate în 2 fluxuri paralele. Userul alege la landing între fluxul text (Discovery + Inspector) și fluxul imagine (Image Match). Mockup-urile sunt statice, dar descrierea pe care o tastezi la pasul 2 se propagă în paginile următoare prin sessionStorage.

Landing — Alege fluxul

Două cards mari: „Am o descriere” și „Am un mockup”. Decizia se ia înainte de orice.

GET /
Flux A — descriere (Discovery + Inspector)
  1. 2

    Formular descriere inițială

    Dropdown tip produs + textarea descriere. La submit, salvează în sessionStorage și se propagă în paginile următoare.

    GET /sessions/new POST /sessions
  2. 3

    Discovery — Întrebări iterative

    Checklist read-only + max 4 întrebări pe rundă. Două stări: în-progres și done=true. Afișează descrierea pe care ai tastat-o la pasul 2.

    GET /sessions/{id} POST /sessions/{id}/answer
  3. 4

    Upload — 1–4 poze

    Slot obligatoriu + 3 opționale, cu preview thumbnails.

    GET /sessions/{id}/validate POST /sessions/{id}/validate
  4. 5

    Raport — Conform / Neconform / Nevizibil

    Trei zone vizuale distincte. Fiecare câmp-frunză al schemei apare exact o dată.

    GET /reports/{id}
Flux B — mockup (Image Match)
  1. 6

    Match — Upload mockup

    Un singur slot pentru artwork. Două stări: gol și completat.

    GET /matches/new POST /matches
  2. 7

    Match — Criterii extrase + upload real

    Listă criterii detectate de analyze_sim + slot pentru poza produsului real. Status DB: awaiting_real.

    GET /matches/{id} POST /matches/{id}/real
  3. 8

    Match — Raport tabelar

    Image pair preview + summary chips + tabel rows. Tipuri match: exact, partial, missing, extra.

    GET /matches/{id}/report
